1. INTRODUCTION                                                *game2048-intro*

2048 for Vim9 is a faithful implementation of the popular 2048 puzzle game,
built entirely in Vim9script. This plugin demonstrates advanced Vim9 features
including classes and objects with proper encapsulation, interfaces for
type-safe contracts, enums for type-safe constants, type aliases for semantic
naming, strict type annotations, modular architecture with clear separation
of concerns, and proper null handling.

The game runs in a Vim popup window and supports both arrow keys and hjkl
navigation keys. This plugin requires Vim 9.0 or later and will not work with
Neovim. The modular design makes it an excellent reference for building
medium-sized Vim9 plugins with professional-grade architecture.

2. INSTALLATION                                            *game2048-install*

Requirements~

This plugin requires Vim 9.0 or later with Vim9 script support enabled.
It will not work with Neovim or older versions of Vim.

Installation~

Using Git~
If you have git installed, run the following command in your terminal:

    Unix/Linux/macOS: >
      git clone https://github.com/yegappan/game2048.git ~/.vim/pack/downloads/opt/game2048
<
    Windows (cmd.exe): >
      git clone https://github.com/yegappan/game2048.git %USERPROFILE%\vimfiles\pack\downloads\opt\game2048
<
Using a ZIP file~
If you prefer not to use Git:

    Unix/Linux/macOS:
    1. Create the destination directory: >

	 mkdir -p ~/.vim/pack/downloads/opt/
<
    2. Download the plugin ZIP file from GitHub and extract its contents into
       the directory created above.

       *Note:* GitHub usually names the extracted folder game2048-main.
       Rename it to game2048 so the final path looks like this: >

	 ~/.vim/pack/downloads/opt/game2048/
	 ├── plugin/
	 ├── autoload/
	 └── doc/
<
    Windows (cmd.exe):
    1. Create the destination directory: >

	 if not exist "%USERPROFILE%\vimfiles\pack\downloads\opt" mkdir "%USERPROFILE%\vimfiles\pack\downloads\opt"
<
    2. Download the plugin ZIP file from GitHub and extract its contents into
       that directory.

       *Note:* Rename the extracted folder (usually game2048-main) to
       game2048 so the path matches: >

	 %USERPROFILE%\vimfiles\pack\downloads\opt\game2048\
	 ├── plugin/
	 ├── autoload/
	 └── doc/

Finalizing Setup~
Since this plugin is installed in the opt (optional) directory, it will not
load automatically. Add the following line to your .vimrc (Unix) or _vimrc
(Windows): >

    packadd game2048
<
After adding the line, restart Vim and run the following command to enable the
help documentation: >

    :helptags ALL
<
Plugin Manager Installation~

If using a plugin manager like vim-plug, add to your .vimrc or init.vim:
>
    Plug 'path/to/game2048'
<
Then run `:PlugInstall` and `:helptags ALL`

For other plugin managers (Vundle, Pathogen, etc.), follow their standard
installation procedures for local plugins.

4. CONTROLS                                         *game2048-controls*

During gameplay, the following keys are active (only within the game popup):

h or <Left>     Move tiles left
l or <Right>    Move tiles right
k or <Up>       Move tiles up
j or <Down>     Move tiles down
r               Reset the current game
q               Close the game window and quit

5. GAME RULES                                              *game2048-rules*

Objective~
The goal of 2048 is to slide numbered tiles on a 4×4 grid to combine them
and create a tile with the number 2048. You can continue playing beyond this
to achieve higher scores.

How to Play~
1. Every turn, you can slide all tiles in one direction: left, right, up, or down
2. When tiles with the same number touch, they merge into one tile with that
   number doubled
3. After each move, a new tile (either 2 or 4) appears in a random empty space
4. Continue until the board is full and no more moves are possible

Scoring~
  • Your score increases by the value of the new tile created when merges occur
  • The scoreboard shows your current score and total moves made
  • Win when you create your first 2048 tile
  • Lose when the board is full with no possible merges (game over state)

Tile Spawning~
After each valid move:
  • A random empty cell is selected
  • 90% probability new tile = 2
  • 10% probability new tile = 4

6. STRATEGY TIPS                                          *game2048-strategy*

Starting Strategy~
1. Keep one corner (usually bottom-right) clear
2. Use that corner as your "dump" area for temporary placement
3. Move high-value tiles gradually toward one edge

Tile Management~
  • Plan multiple moves ahead when possible
  • Avoid creating scattered tiles that can't be merged
  • Keep larger tiles on one side of the board
  • Create opportunities for merge cascades

Progression Technique~
  • Focus on building one large tile at a time
  • Work systematically toward the 2048 goal
  • Don't rush to merge tiles randomly
  • Keep the board as organized as possible

Advanced Play~
  • Once 2048 is reached, continue for 4096, 8192, etc.
  • The highest possible tile depends on your strategy and board luck
  • Higher scores require careful planning and patience

7. CONFIGURATION                                         *game2048-config*

The 2048 plugin is designed to work out of the box with no configuration
needed. However, the modular architecture could be extended to support:

Potential Configuration Options~

  • g:game2048_board_size: Grid dimensions (currently 4x4)
  • g:game2048_target_tile: Winning tile value (currently 2048)
  • g:game2048_spawn_new_tile: Probability of new tile (currently 90% "2")
  • g:game2048_popup_height/width: Popup window dimensions
  • g:game2048_animation_speed: Tile merge animation speed
  • g:game2048_color_scheme: Custom color palette for tiles

Current Defaults~

Board Configuration:
  • Grid Size: 4 x 4
  • Target Score: 2048
  • Spawn Probability: 90% tile with value 2, 10% with value 4
  • Popup Position: Centered in window

Gameplay Settings:
  • Move Validation: Only valid moves are executed
  • Scoring: Cumulative merge values
  • Game Over Detection: Board full with no valid merges
  • Continue After Win: Yes, play toward beyond 2048

Customization in the Code~

To adjust these values, edit: >>
  autoload/game2048/constants.vim
<
Then modify constants like:
  const GRID_SIZE = 4
  const TARGET_SCORE = 2048
  const NEW_TILE_PROBABILITY = 0.9

After changes, restart Vim or reload the plugin.

8. VIM9 SCRIPT FEATURES                            *game2048-vim9*

This plugin demonstrates several modern Vim9script capabilities:

Classes~
  • GameBoard: 4×4 grid management and 2048 game mechanics
  • Game: Main controller implementing IGame interface
  • GameUI: Popup rendering and input implementing IGameUI interface

Interfaces~
Type-safe contracts for game components:
>
    interface IGame
      def Reset(): void
      def HandleInput(direction: Direction): void
      def Close(): void
    endinterface

    interface IGameUI
      def Show(): void
      def Hide(): void
      def SetGameInstance(game: IGame): void
      def Update(): void
    endinterface
<

Enum~
Direction enum provides type-safe movement constants:
>
    enum Direction
      LEFT,
      RIGHT,
      UP,
      DOWN,
    endenum
<

Type Aliases~
Semantic type aliases improve code readability:
>
    type Position = list<number>   " [row, col] coordinate pair
<

Type Checking~
Strict type annotations throughout:
  • All function parameters have explicit types
  • Return types specified on all functions
  • Loop variables typed: for row: number in range(...)
  • Collections fully typed: list<list<number>>, dict<any>
  • Nullable objects: var _ui: IGameUI = null_object

Module Architecture~

The plugin uses a modular architecture with clear separation of concerns:

  constants.vim
    Game configuration (GRID_SIZE, POPUP_WIDTH, TARGET_SCORE, etc.)
    No dependencies

  types.vim
    Type aliases, Position type, Direction enum
    IGame and IGameUI interface contracts
    No dependencies

  game_board.vim
    GameBoard class with 2048 mechanics
    Move(), MergeLine(), CompressLine(), CanMove() algorithms
    Score and state tracking
    Dependencies: constants, types

  ui.vim
    GameUI class for popup rendering
    FilterKey() for input handling
    GenerateDisplay() for board rendering
    Dependencies: constants, types, game_board

  game.vim
    Game class coordinating board and UI
    Implements IGame interface
    Dependencies: types, game_board, ui

  game2048.vim (Main Entry Point)
    GetGameInstance() - singleton game instance
    CloseGame() - cleanup and shutdown
    Public API for the plugin
    Dependencies: types, game

Design Patterns~

Interface-Based Design
    IGame and IGameUI interfaces break circular dependency
    Game refers to IGameUI (not GameUI)
    GameUI refers to IGame (not Game)
    Enables loose coupling and better testability

Singleton Pattern
    Game instance managed at module level
    GetGameInstance() lazily creates game on first call
    game_instance set to null_object after CloseGame()

Strict Type Safety
    No 'any' types for game domain objects
    Explicit type annotations prevent runtime errors
    null_object used correctly for nullable objects
    Enum usage for direction constants
